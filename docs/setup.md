# 部署与恢复

## 准备

先记录型号、系统、活动播放器版本、电视当前地址、DNS和原配置。电脑和电视同网，ADB仅用于已授权设备。不要扫描或控制其他设备。

从上游获取过滤器并核验版本与校验值。本项目历史使用FlClash v0.9.3 ARMv7，SDK28电视；这是当时的兼容记录。安装前应核对自己设备ABI及上游当前版本说明。

## 分阶段验证

1. 在电视本地完成调试、安装与VPN询问。先用默认直连确认首页和免费内容正常。
2. 导入examples/tv-filter.yaml，核查实际启用的配置。测试原首页同一集，记录广告、倒计时、黑屏和首帧时间。
3. 仅在机型和播放器读取路径已经确认时实验架构文档中的属性。先记录每个属性原值，单项变更、失败恢复，再综合复验。
4. 根据架构实现启动助手后，本地允许后台自启动与保持后台运行。关闭重复启动工具，避免多个助手争抢前台。
5. 取消对Mac临时配置服务器的自动更新依赖，确认缓存/本地配置可用。电视DNS指向家庭原DNS；本例最终使用路由器DNS。
6. 分别验证系统重启、遥控器关开、真实断电，以及Mac断网时从原首页点剧。每次检查过滤器、VPN、属性和真实画面。

只需读取设备时，可用以下占位符示例。TV_IP替换为实时核对的电视地址。

```sh
adb connect TV_IP:5555
adb -s TV_IP:5555 shell pidof com.follow.clash
adb -s TV_IP:5555 shell getprop debug.ottsdk.ups_ad
adb -s TV_IP:5555 shell getprop debug.ottad.mid.forbiddentime
```

## 回退

联网或正片异常时，先在FlClash正常停止过滤，恢复此前DNS/动态IP并从原首页重测。关闭助手开机开关，恢复实验前逐项记录的属性值。空值也须按原状态恢复；重启前先停用自动重写，随后重新读取属性核对。不要以清除播放器数据或卸载系统组件作为首选。

旧助手包需使用同一签名、满足系统版本升级规则后才能覆盖安装。原项目保留0.2兼容恢复包，但文档整理没有执行新回滚，不能称已验证此次回退。
